--- typecheck ---

because the tsconfig lib set (ES2022/DOM, no @types/node) does not declare Node's `global`.

Final result: exit 0, no errors.

--- runtime smoke test ---
1. Started apps/api (uvicorn, port 8000) — GET /health -> {"status":"ok"}
2. Started `npm run preview -- --host 127.0.0.1 --port 3000` (serves the production dist/ build)
3. GET http://127.0.0.1:3000/ -> HTTP 200, returned index.html referencing the built JS/CSS assets
4. Fetched the built JS bundle and confirmed the string "http://localhost:8000" is present
   (1 occurrence) — proves VITE_API_URL was correctly inlined at build time and points at the
   locally running API. (Full in-browser Header connectivity behavior is covered by the
   Header.test.tsx unit tests using jsdom + mocked fetch, since no browser automation tool was
   used for this manual smoke test.)
5. Both dev processes (uvicorn, vite preview) were stopped after verification.

--- docker build / docker compose up ---
Command: docker build (via `docker info`) / `docker compose up`
Result: NOT EXECUTED — Docker Desktop daemon is not running locally
("failed to connect to the docker API at npipe:////./pipe/dockerDesktopLinuxEngine"), the same
limitation recorded for PBI-00-02. Dockerfiles for both apps/api and apps/web were authored per
the required file trees and reviewed manually; docker-compose.yml was structurally validated via
`docker compose config`. Actual image builds and container startup remain unverified pending a
running Docker daemon.

--- Conclusion ---
The minimal Web application (chat-style layout: header with connectivity/version status, sidebar
placeholder, message area with synthetic welcome content, input+Send) is implemented, lint-clean,
type-clean, unit-tested (7/7), and builds successfully. The API-connectivity wiring was verified
end-to-end at the network level (built bundle -> running API) short of a real browser. Docker
Compose was fixed (VITE_API_URL moved from runtime `environment` to build-time `args`, since Vite
inlines env vars at build time) and structurally validated; actual container builds are deferred
until Docker Desktop's daemon is available in this environment.
