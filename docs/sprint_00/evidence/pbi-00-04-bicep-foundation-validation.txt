--- az bicep build (main.bicep, transitively validates all modules) ---
Command: az bicep build --file ops/bicep/main.bicep --outdir <tmp>
Attempt 1: FAILED
  - Warning secure-secrets-in-params on key-vault.bicep param 'secretsUserPrincipalId' (name
    contained the substring "secret", tripping the linter's secret-name heuristic even though the
    value itself is a non-secret principal ID). Fixed by renaming the parameter to
    'keyVaultAccessPrincipalId'.
  - Error BCP181 (x2) in main.bicep: reference()/listKeys() were called with
    logAnalytics.outputs.id, a module-output-derived expression, which Bicep cannot treat as
    "calculable at the start of deployment" even though its value is deterministic. Fixed by
    building the resourceId() from the main.bicep-level `logAnalyticsName` variable instead
    (a plain expression over input parameters), and added an explicit `dependsOn: [logAnalytics]`
    on the containerAppsEnvironment module, since referencing the variable instead of the module
    output removes the automatic dependency edge Bicep would otherwise infer.
Attempt 2: PASSED — exit 0, no errors, no warnings.

--- Manual "no hardcoded values" review ---
Searched ops/bicep for: GUID-shaped literals, resource-group-name literals, hardcoded
https:// endpoints, password/secret/apikey/connectionstring literal assignments, and literal
image tags in parameter files.
Findings:
  - Two GUID literals found: '7f951dda-4ed3-4680-a7ca-43fe172d538d' (container-registry.bicep)
    and '4633458b-17de-408a-b874-0445c86b69e6' (key-vault.bicep). Both are Microsoft's public,
    fixed built-in RBAC role-definition IDs (AcrPull, Key Vault Secrets User respectively) —
    not subscription/tenant IDs or secrets. This is the standard, expected way to reference
    built-in roles in Bicep IaC.
  - One https:// match: an illustrative CLI example inside a code comment in main.bicep
    ("--build-arg VITE_API_URL=https://<apiContainerAppFqdn>"), not a real endpoint.
  - No resource group name literals, no credentials/secrets, no company-internal names.
  - apiImageTag/webImageTag in all three parameter files are the placeholder string
    'pending-first-build', not a real image tag — parameterized and environment-supplied, and
    explicitly documented as requiring replacement by the future CI/CD pipeline (PBI-00-07)
    before any real deployment.
