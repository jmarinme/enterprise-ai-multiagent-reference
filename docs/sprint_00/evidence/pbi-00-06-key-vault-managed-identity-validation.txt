--- Backend: dependency installation ---
Added optional `keyvault` extra to root pyproject.toml (azure-keyvault-secrets, azure-identity).
Installed into the existing root .venv (Python 3.11.9): azure-keyvault-secrets 4.11.0.

Real issue discovered and fixed: constructing AzureKeyVaultSecretProvider (which builds an async
DefaultAzureCredential) failed with "ImportError: aiohttp package is not installed" — the async
azure-identity credential chain requires aiohttp for its default async HTTP transport, which is
not a transitive dependency of azure-identity/azure-cosmos/azure-keyvault-secrets. This was a
latent gap in PBI-00-05's `cosmos` extra too (never exercised there because no unit test
constructed a real, unmocked CosmosConversationRepository). Fixed by adding `aiohttp>=3.9,<4` to
both the `cosmos` and `keyvault` extras. Installed aiohttp and re-ran; all tests passed.

--- Naming collision discovered and fixed ---
The new `src/services/secrets/` directory was silently matched by the repository's own
`.gitignore` rule `secrets/` (line 8, intended to block accidentally-committed local secret
files) — `git status` never listed any of its files as untracked. Confirmed via
`git check-ignore -v`. Fixed by renaming the module to `src/services/secret_store/` (mirroring
the existing `src/services/conversation_store/` naming from PBI-00-05) rather than editing the
security-relevant `.gitignore` rule. Re-validated after rename: `git check-ignore` now reports
the path is not ignored, and `git status` correctly lists it as untracked/ready to add.
