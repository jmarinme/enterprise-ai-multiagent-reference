  Root cause found: Azure OpenAI addresses deployments by an arbitrary ALIAS
  (AZURE_OPENAI_DEPLOYMENT="chat" in this template), never by the real model name
  ("gpt-5-mini"). The _is_reasoning_model(model) check used `model = request.settings.model

  "gpt-5", so the check silently never matched. A real bug in the PBI's own fix, caught only
  by testing against the real deployed service.

  User direction: pass the real model name through explicitly (not react to the API's error
  text) -- more robust, matches "capability-aware" intent, touches Bicep + settings +
  composition root in addition to AzureOpenAIProvider, still zero Agent/business code.

  Fix:
    - ops/bicep/modules/azure-openai.bicep: new `output modelName string = modelName`

      AZURE_OPENAI_MODEL_NAME via pydantic-settings' default field-name-to-env-var mapping)
    - src/llm/azure_openai_provider.py: new AzureOpenAIProvider(model_name=...) constructor
      param, defaults to `deployment` when unset (zero behavior change for any caller that
      omits it); generate() now uses self._model_name (not the deployment alias `model`) for
