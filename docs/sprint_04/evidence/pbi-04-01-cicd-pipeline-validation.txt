3. PIPELINE YAML — REWRITE AND VALIDATION
=====================================================================

Rewrote azure-pipelines.yml in place (not a new file):
  - Preserved Stage 1 (BackendQuality) and Stage 2 (FrontendQuality) structurally, adding
    Cache@2 tasks (pip keyed on both pyproject.toml files; npm keyed on package-lock.json) to
    satisfy the "cache packages" requirement explicitly.
  - Preserved Stage 3 (InfrastructureValidation), fixed the stale bicepModuleFiles list (see
    above).
  - Replaced Stage 4 (ContainerBuildValidation, build-only, buggy context) with
    ContainerBuildAndPush (build + push combined into one stage — see decisions.md for why;
    fixed build context; resolves the existing API Container App's real FQDN to correctly bake
    VITE_API_URL into the Web image build).
  - Replaced the disabled (condition: false) Deploy_Dev stage with an ENABLED DeployDev stage:
    targeted `az containerapp update --image` only, resolved dynamically, unique
    dev-$(Build.BuildId) tag, never `az deployment group create`.
  - Added new SmokeTests stage: GET /health, POST /chat, fails the pipeline on any failure.
  - Added new DeploymentSummary stage: image tags, deployed apps/revisions, execution time,
    test summary (parsed from the backend/frontend JUnit artifacts), published as a pipeline
    artifact and via ##vso[task.uploadsummary].
  - Kept ArtifactPublication (IaC + validation summary, every run — not deploy-gated).
  - New pipeline parameters: azureServiceConnection (default
    'tmx-agent-platform-dev-oidc'), resourceGroupName (the only hardcoded resource name —
    'rg-tmx-agent-platform-dev', stable/non-generated), deployBranch (default 'main').
  - New variable isDeployRun gates Stages 4-8 to pushes on deployBranch only.
