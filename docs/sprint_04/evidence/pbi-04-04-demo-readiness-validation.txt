FIVE BUGS FOUND AND FIXED VIA LIVE VALIDATION (full rationale in decisions.md)
------------------------------------------------------------------
1. Customer lookup deferred until every incident-detail field was collected,
   instead of right after the name — reordered _handle_collecting_information.
2. Vehicle-description matching compared the strings backwards ("la Hilux"
   can never contain "Toyota Hilux 2021") — fixed to word-set intersection.
3. A combined/grouped question silently dropped its free-text field
   (event_location) when a structured field (event_date) matched in the same
   message — new ClaimsIntakeState.last_asked_group + group-aware recovery.
4. Declining the confirmation step created a silent dead loop (nothing was
   cleared, so the next turn walked straight back to the same summary) —
   decline now clears the correctable incident-detail fields.
5. GET /conversations only accepted "user_id", not the "userId" every other
   caller on this API actually uses — fixed with Query(alias="userId").

Each was fixed, covered by a new regression test, and re-validated live
before moving to the next (never batched).
