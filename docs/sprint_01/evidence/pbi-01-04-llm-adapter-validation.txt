--- Conclusion ---
The LLM Adapter framework mirrors the Supervisor/Tool/Prompt frameworks' proven interface-only
shape a fourth time: Agents depend only on LLMProvider, never on the openai or azure-identity
SDKs. MockLLMProvider is fully deterministic and is the default, so every test and local dev
run requires zero Azure connectivity. AzureOpenAIProvider is production-shaped (typed settings,
no hardcoded endpoint/deployment/key, Entra ID preferred, API-key auth routed only through
SecretProvider, typed exception normalization from the real openai SDK's exception hierarchy,
async throughout) but is never called during tests — all 9 of its tests fully mock the
`openai`/`azure-identity` SDK boundary. ClaimsAgent now demonstrates real LLMProvider injection
with a response that legitimately varies per input (proving the integration is real) while
remaining fully deterministic for a given input (proving MockLLMProvider enables reliable local
development and testing). All 136 tests pass deterministically with no Azure dependency; ruff
and mypy clean. No RAG, Azure AI Search, embeddings, vector databases, Semantic Kernel,
AutoGen, LangGraph, CrewAI, APIM, or authentication was implemented.
